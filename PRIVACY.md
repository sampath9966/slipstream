# Privacy Policy — Slipstream Claude Code Plugin

**Effective date:** 2026-09-20
**Last updated:** 2026-09-20
**Maintainer:** sampath9966 · sampath@vmwareadmin.in

---

## 1. Overview

Slipstream is a developer productivity plugin for Claude Code. This policy describes what data Slipstream accesses, where it is stored, and what guarantees users have regarding their information.

**Summary:** Slipstream collects nothing from you and sends nothing anywhere. All data it writes stays on the device where it runs, under paths you control, and is deleted when you choose to delete it.

---

## 2. What data Slipstream reads

Slipstream reads the following data sources — all local, all on the user's own machine or container:

| Source | Purpose | Leaves device? |
|--------|---------|----------------|
| Claude Code session transcript (`~/.claude/projects/…/*.jsonl`) | Count tokens per turn to build the burn ledger | **No** |
| Repository working directory path | Write the per-repo session cache (`.slipstream/last-session.json`) | **No** |
| `~/.local/share/slipstream/config.json` | Read user-configured thresholds and pricing rates | **No** |
| `~/.local/share/slipstream/ledger.db` | Read/write the rolling 7-day SQLite burn ledger | **No** |
| `.slipstream/last-session.json` (in the repo) | Read and write the last-session token summary | **No** |

Slipstream does **not** read:
- The content of your conversations with Claude
- Any file outside the paths listed above
- Environment variables, credentials, SSH keys, or secrets
- System information beyond the working directory path

---

## 3. What data Slipstream writes

Slipstream writes only to local paths on the user's machine or container:

### 3a. SQLite ledger (`~/.local/share/slipstream/ledger.db`)

Written by the `Stop` hook after each Claude Code session. Contains:
- Session ID (a UUID generated by Claude Code)
- Timestamp
- Token counts by type: `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`
- File paths read during the session (for re-read waste analysis)
- Tool names called during the session

No conversation content is stored. No personal data beyond what is listed above.

### 3b. Repo-level session cache (`.slipstream/last-session.json`)

Written to the repository root after each session. Contains the same token counts and an estimated dollar cost. This file may be committed to version control if the user chooses; it contains no conversation content and no credentials.

### 3c. Config file (`~/.local/share/slipstream/config.json`)

Written during first-run setup. Contains user-configured thresholds (e.g. warn at 70%) and pricing rates (e.g. $3.00/MTok). No personal data.

---

## 4. Data transmission

**Slipstream transmits no data to any external service, server, API, or third party — ever.**

There are no:
- Analytics endpoints
- Crash reporting services
- Telemetry beacons
- Remote configuration fetches
- License validation calls
- Update checks that phone home

Network access is never initiated by Slipstream. The plugin has no network dependency.

---

## 5. Data retention and deletion

All Slipstream data resides on the user's device. Users may delete it at any time:

```bash
# Delete the burn ledger (resets all 7-day history)
rm ~/.local/share/slipstream/ledger.db

# Delete config (resets to defaults on next run)
rm ~/.local/share/slipstream/config.json

# Delete the repo session cache
rm .slipstream/last-session.json

# Delete everything
rm -rf ~/.local/share/slipstream/ .slipstream/
```

Slipstream does not recreate deleted data until a new Claude Code session completes with the plugin active.

---

## 6. Data in version control

If a user commits `.slipstream/last-session.json` to their repository, they are sharing:
- Token counts from their last session
- An estimated session cost
- Their Claude model name

They are **not** sharing conversation content, file content, or credentials. Users should review this file before committing if they prefer to keep session economics private. The repository's `.gitignore` may be updated to exclude `.slipstream/` if preferred.

## 7. Children's privacy

Slipstream is a developer tool intended for adults. It does not knowingly collect any information from children under the age of 13 (or the applicable age of digital consent in the user's jurisdiction).

## 8. GDPR and regional compliance

Slipstream does not act as a data controller or data processor under the GDPR, CCPA, or equivalent regulations because:
- It processes no personal data on behalf of any third party
- It stores data exclusively on the user's own device
- It has no mechanism to receive, retrieve, or share user data

Users in the European Economic Area, United Kingdom, California, and other regulated jurisdictions retain full control over all data because all data is local.

---

## 9. Third-party dependencies

Slipstream's runtime dependencies are:
- **Python 3 standard library** (`sqlite3`, `json`, `pathlib`, `subprocess`) — included with Python; no network access
- **No external packages** are required or fetched at runtime

---

## 10. Security

Slipstream writes files with default OS permissions (user-readable/writable, not world-readable). The SQLite ledger is not encrypted; users who require encryption at rest should apply filesystem-level encryption (e.g. FileVault, LUKS, BitLocker) independently.

Slipstream does not execute arbitrary code from network sources. All logic is contained in the repository and runs locally.

To report a security vulnerability, email **sampath@vmwareadmin.in** with subject line `[SECURITY] Slipstream`. We will respond within 5 business days.
